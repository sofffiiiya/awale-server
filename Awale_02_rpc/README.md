# Awalé game server (Sun RPC version)

TP 2/3/4, 4IF Networks, INSA Lyon.

A client/server Awalé game written in C. Players log in with a username, see who is online,
challenge each other and play. The server checks every move, keeps the score and sends the board
to the players and to spectators. Players can also chat, write a bio, choose who may watch their
games, and replay saved games.

The client and the server talk with **Sun RPC** (the interface is in `awale_rpc.x` and the network
code is generated by `rpcgen`).

## 1. Features

| Feature | Commands |
|---|---|
| Log in with a username | `./client <host> <username>` |
| List of online users | `/list` |
| Challenge a user, accept or refuse a challenge | `/challenge`, `/accept`, `/refuse` |
| The server chooses at random who starts, and checks that every move is legal | `/move` |
| Several games at the same time, list of ongoing games | `/games` |
| Spectator mode | `/watch`, `/unwatch` |
| Chat inside and outside a game, private messages | plain text, `/all`, `/msg` |
| Bio of up to 10 lines, shown for any user (also offline) | `/bioadd`, `/bio`, `/bioclear` |
| Private mode: only friends can watch my games | `/private`, `/friend`, `/friends` |
| Every finished game is saved and can be replayed | `/saved`, `/replay` |
| A player who loses the connection can come back in his game | log in again with the same name |

## 2. Compilation

Linux (Debian / Ubuntu, also works in WSL on Windows).

Install the compiler and the RPC tools once:

```
sudo apt install build-essential rpcbind rpcsvc-proto libtirpc-dev
```

- `rpcsvc-proto` contains `rpcgen`
- `libtirpc-dev` is the RPC library
- `rpcbind` is the RPC "port mapper", it must run on the server machine

Then compile:

```
make
```

`make` first runs `rpcgen awale_rpc.x`, which generates `awale_rpc.h`, `awale_rpc_clnt.c`,
`awale_rpc_svc.c` and `awale_rpc_xdr.c`, then builds three programs:

| Program | What it is |
|---|---|
| `server` | the game server |
| `client` | the client used by each player |
| `local` | the Awalé game alone, two players on one keyboard, no network (step 0 of the project) |

Other targets: `make clean` removes the programs and generated files, `make distclean` also removes
saved games and profiles.

## 3. Running the server

`rpcbind` must be running first. On most systems it starts by itself. If not:

```
sudo systemctl start rpcbind     # or simply: sudo rpcbind
```

Then, from the `Awale_02_rpc` folder:

```
./server
```

The server does not ask anything. It prints a line when somebody logs in, logs out or times out.
Stop it with `Ctrl+C`.

If the server prints `unable to register`, `rpcbind` is not running (or the server must be started
with `sudo`).

You can check that the server is registered with `rpcinfo -p`: the program number `536871319`
(0x20000197) must appear in the list.

## 4. Running a client

```
./client <server host> <username>
```

Examples:

```
./client localhost alice          # server on the same computer
./client 192.168.1.20 bob         # server on another computer of the network
```

The username must have 1 to 15 characters: letters, digits, `_` or `-`. Two connected users can not
have the same name.

After that, type commands (they start with `/`) or chat messages, one per line. `/help` shows the
list of commands. `/quit` leaves.

**Playing on two computers.** The client only needs the IP address of the server machine. The
server machine must accept incoming connections on port 111 (`rpcbind`) and on the port chosen by the
server (shown by `rpcinfo -p`), so a firewall may have to be opened. If the server runs in WSL, WSL
must be in "mirrored" network mode, otherwise other computers can not reach it.

## 5. User manual: all the commands

### Users

| Command | What it does |
|---|---|
| `/help` | shows the list of commands |
| `/list` | shows the online users and what they are doing (available, playing, watching, disconnected) |
| `/quit` | leaves (during a game, see [section 7](#7-disconnection-and-reconnection)) |

### Challenges and games

| Command | What it does |
|---|---|
| `/challenge <user>` | asks `<user>` for a game |
| `/accept <user>` | accepts the challenge of `<user>`: the game starts |
| `/refuse <user>` | refuses the challenge of `<user>` |
| `/move <1-6>` | plays one of your pits (only when it is your turn) |
| `/board` | shows the board of your game again |
| `/abandon` | gives up the current game (you lose) |
| `/games` | lists the ongoing games with their number, players, scores and number of spectators |

### Spectators

| Command | What it does |
|---|---|
| `/watch <game number>` | watch a game: you get the board after every move and the game chat |
| `/unwatch` | stop watching |

A player can not watch another game while playing.

### Chat

| Command | What it does |
|---|---|
| `<text>` | a line that does not start with `/` is a chat message: it goes to the people of your game (players and spectators) if you play or watch one, otherwise to everybody |
| `/all <text>` | message to everybody |
| `/msg <user> <text>` | private message to one user |

### Bio

| Command | What it does |
|---|---|
| `/bioadd <text>` | adds one line to your bio (10 lines maximum, non ASCII characters become `?`) |
| `/bio` | shows your bio |
| `/bio <user>` | shows the bio of `<user>`, even if he is not connected |
| `/bioclear` | erases your bio |

### Private mode and friends

| Command | What it does |
|---|---|
| `/private on` | only your friends can watch your games. Spectators who are not your friends are removed from your current game |
| `/private off` | everybody can watch your games |
| `/private` | shows if private mode is on or off |
| `/friend add <user>` | adds `<user>` to your friends (20 maximum) |
| `/friend del <user>` | removes `<user>` from your friends |
| `/friends` | shows your friends and which ones are online |

A game where one of the players is in private mode is marked `[private]` in `/games`.
The bio, the friends list and the private mode are kept between connections.

### Saved games

| Command | What it does |
|---|---|
| `/saved` | lists the finished games kept by the server, with a number |
| `/replay <number>` | shows that game again, move by move, with the board after each move |

## 6. Playing a game

```
alice:  /challenge bob
bob:    /accept alice
```

The server chooses who starts and sends the board to both players:

```
   bob : 0 seeds captured
     6    5    4    3    2    1
   +----+----+----+----+----+----+
   |  4 |  4 |  4 |  4 |  4 |  4 |  <- bob
   +----+----+----+----+----+----+
   |  4 |  4 |  4 |  4 |  4 |  4 |  <- alice
   +----+----+----+----+----+----+
     1    2    3    4    5    6
   alice : 0 seeds captured
It is YOUR turn: /move <1-6>
```

Each player numbers **his own** pits from 1 to 6 (the numbers printed on his side of the board).
Seeds move counter-clockwise: from left to right on the bottom row, from right to left on the top row.

Rules (as on the French Wikipedia page, "abapa" variant):

- A player takes all the seeds of one of his non-empty pits and sows them one by one in the next pits.
  With 12 seeds or more, the starting pit is skipped.
- If the last seed falls on the opponent's side and the pit then has **2 or 3** seeds, they are
  captured. Then the pit before is checked, and so on, as long as it is on the opponent's side with
  2 or 3 seeds.
- A move that would take **all** the seeds of the opponent is allowed but captures nothing ("grand slam").
- If the opponent has no seeds, the player **must** play a move that gives him some. If no such move
  exists, the game ends and each player takes the seeds left on his side.
- The first player with **25** seeds or more wins. 24-24 is a draw.

The server refuses illegal moves and says why (`this pit is empty`, `it is not your turn`, ...).
At the end, everybody in the game gets the result, and the game is saved.

## 7. Disconnection and reconnection

- A client that quits (`/quit`, `Ctrl+D`) or stops answering for 30 seconds (window closed,
  network lost) is disconnected.
- If he was **not** in a game, he simply leaves.
- If he **was** in a game, the game is **paused**: the opponent and the spectators are told,
  `/list` shows him as `disconnected (game N paused)`, and no move can be played.
- If he logs in again **with the same name within 2 minutes**, he gets back his game, his bio and his
  friends, the board is sent to everybody, and the game continues.
- If he does not come back in time, he loses the game, and the game is saved with the reason
  `<name> did not come back`.

`/abandon` is the way to really give up a game.

## 8. Files written by the server

The server creates two folders in the folder it is started from:

| Folder | Content |
|---|---|
| `profiles/` | one file per user (`<name>.txt`): private mode, friends, bio |
| `games/` | one file per finished game (`<time>_<player0>_vs_<player1>.txt`) |

A saved game contains the players, who started, the list of moves and the result, for example:

```
players alice bob
first 1
moves 8 2 11 4
result alice 26 - 20 bob : the game is finished, alice wins
```

`/replay` plays the moves again with the game code, so the boards shown are exactly those of the game.

## 9. How it works inside

RPC works by request and answer: only the client can call the server, the server can not send
anything by itself. So the server keeps a **mailbox** for every user:

- Everything for a user (board after a move, chat message, challenge, ...) is added to his mailbox.
- `COMMAND` sends one line typed by the user. The server runs it and answers with the mailbox
  content, so the player sees the result of his command at once.
- The client calls `POLL` by itself **every 2 seconds** to get what happened meanwhile
  (the opponent's move, messages...).
- A client that has not called the server for 30 seconds is considered disconnected.

RPC procedures (`awale_rpc.x`):

| Procedure | What it does |
|---|---|
| `LOGIN(name)` | logs in, returns a secret token sent with every next call |
| `COMMAND(token, line)` | runs one command, returns the answer |
| `POLL(token)` | returns and empties the mailbox |
| `LOGOUT(token)` | logs out |

All the commands go through the same text protocol (`commands.c`), so adding a feature means
adding one `cmd_...` function and one line in `command_handle()`. The rules of the game are only in
`awale.c`, separated from the network.

## 10. Source files

| File | Content |
|---|---|
| `awale_rpc.x` | the RPC interface (input of `rpcgen`) |
| `awale_server.c` | server side of the RPC procedures, timeouts |
| `awale_client.c` | the client: reads the keyboard, sends commands, polls every 2 seconds |
| `awale.c`, `awale.h` | the rules of Awalé and the ASCII board, no network |
| `game.c`, `game.h` | games: creation, moves, spectators, private mode, end, saving, replay |
| `commands.c`, `commands.h` | the text protocol: one function per command, login, disconnection, reconnection |
| `user.c`, `user.h` | connected users, mailboxes, friends, profiles |
| `local.c` | the game without network, two players on one keyboard |
| `Makefile` | compilation |

Limits (constants in the `.h` files): 100 users, 50 games at the same time, 20 spectators per game,
20 friends, 10 bio lines of 80 characters.
